# PQ 경력평가 웹 프로그램 — 설계 (v1)

- 작성일: 2026-10-06
- 대상 평가기준: 비탈면·옹벽 정밀안전진단 및 성능평가용역 PQ 평가기준(2026, 재난관리처)
- 범위: **가-2) 참여기술인 경력** 1개 항목 (등급·실적은 다음 단계)

## 1. 목적

건설기술인 경력증명서(스캔 PDF)를 올리면, 평가기준을 준용해 행별 인정여부·인정율·환산일수·점수를 산정한
**평가시트(엑셀)** 를 만들어 준다. 평가위원은 그 엑셀의 'PQ 평가위원 평가' 칸에서 AI 판단의 적정 여부를 확인·입력한다.
평가위원 입력은 이후 AI 판단 정확도를 판단하는 자료로 쓴다.

### 원칙
- 평가기준 원문에 충실. 원문만으로 정할 수 없는 건은 추측하지 않고 **확인필요**로 표시한다.
- 같은 입력이면 항상 같은 판정이 나와야 한다 → 판정은 규칙 기반(LLM 미사용).
- 판독(OCR)만 Gemini를 쓰고, 판독 결과는 증명서 자체 합계표로 자동 대조한다.

### 사용 환경
- 사용자 PC 1대, 1인 사용. Python 서버를 띄우고 브라우저(localhost)로 접속.
- 인터넷은 Gemini API 호출에만 사용. 경력증명서 쪽 이미지가 Gemini(구글)로 전송된다는 점을 화면에 고지한다.

## 2. 처리 흐름

```
업로드(PDF + 성명(마스킹)·소속·참여형태)
 → pdf_pages      : PDF → 쪽 PNG(150dpi)
 → reader_gemini  : 쪽 분류 + 쪽별 구조화 판독(JSON)
 → crosscheck     : 증명서 '공사종류별 인정일수 현황'과 판독 합계 대조
 → rules          : 행별 판정(유사/관련/불인정, 인정율, 근거, 확인필요)
 → scoring        : 환산일수·환산년수·참여형태별 점수
 → excel_export   : 평가시트 xlsx 생성
 → 웹 결과 화면 + 엑셀 다운로드
```

## 3. 구성 요소

| 모듈 | 책임 | 입력 → 출력 | 의존 |
|---|---|---|---|
| `pdf_pages` | PDF를 쪽 이미지로 | PDF 경로 → PNG 경로 목록 | pymupdf |
| `reader_gemini` | 쪽 분류·판독, 재시도 | PNG → `PageResult`(JSON) | Gemini API |
| `assemble` | 쪽 결과를 경력 행 목록으로 합침(쪽 넘김 └→ 병합) | `PageResult[]` → `CareerRow[]` + `CertInfo` + `CertTotals` | — |
| `crosscheck` | 형식 검사 + 합계 대조 | `CareerRow[]`, `CertTotals` → `CheckReport` | — |
| `rules` | 경력 판정 | `CareerRow` + 규칙 파일 → `Judgement` | YAML 규칙 |
| `scoring` | 환산·점수 | `Judgement[]` + 참여형태 → `Score` | YAML 배점표 |
| `excel_export` | 평가시트 생성 | 평가 데이터 → xlsx | openpyxl |
| `store` | 평가 1건 = 폴더 1개 저장·조회 | — | 파일시스템 |
| `server` / `web` | 업로드·진행·결과·다운로드 화면 | HTTP | FastAPI, HTML/JS |

각 모듈은 단독으로 시험 가능해야 한다. 판독(`reader_gemini`)을 빼고도 `CareerRow` JSON만 있으면 판정~엑셀이 돈다.

## 4. 데이터

### CareerRow (경력 행 1개)
`구분`(기술경력 | 건설사업관리·감리), `시작일`, `종료일`(날짜 또는 '근무중'), `인정일`(정수), `사업명`, `발주자`,
`공사종류`, `직무분야`, `전문분야`, `담당업무`, `직위`, `공사개요`, `금액`, `시설물종류`, `쪽`(PDF 쪽 번호).

### CertInfo (1쪽)
성명, 등급(직무·전문분야별), 국가기술자격, 교육훈련, 근무처(기간·상호).

### CertTotals (분야별 인정일 쪽)
공사종류별 인정일수, 직무/전문분야별 인정일수, 합계.

### 저장 구조 (평가 1건)
```
data/evaluations/<YYYYMMDD-HHMM>_<성명>/
  meta.json          성명·소속·참여형태·기준·모델·생성시각
  source.pdf
  pages/p01.png ...
  raw/p01.json ...   Gemini 원본 응답 (클로드 코드 사후 검증용)
  rows.json          CareerRow[] + CertInfo + CertTotals
  check.json         CheckReport
  judgements.json    Judgement[] + Score
  평가시트_<성명>.xlsx
```

## 5. 판독 (Gemini)

- 쪽 종류: `인적사항`(1쪽) / `기술경력` / `건설사업관리감리` / `분야별인정일` / `기타`.
- 1차 호출로 쪽 종류 + 해당 종류의 필드를 함께 구조화 출력(JSON 스키마 강제).
- 형식 오류·응답 실패 시 그 쪽만 최대 2회 재시도. 계속 실패하면 `실패 쪽 목록`에 기록하고 진행.
- 모델명·API 키는 `.env`(`GEMINI_API_KEY`, `GEMINI_MODEL`)에서 읽는다. 사용 가능한 모델은 구현 시 확인.
- 쪽 넘김 행(└→ 표시, 날짜 없이 내용만 이어지는 칸)은 `assemble`이 직전 행에 병합.

### 자동 검증 (crosscheck)
1. 형식: 날짜 형식, 시작 ≤ 종료(또는 근무중), 인정일 정수 ≥ 0.
2. 합계 대조: 공사종류별 판독 합계 vs 증명서 합계.
   - 0 ≤ (증명서 합계 − 판독 합계) ≤ 해당 공사종류 행 수 → **정상**
     (증명서 주석: 참여기간 중복 시 행마다 소수점 이하 절삭 → 행당 1일 미만 차이 가능).
   - 판독 합계 > 증명서 합계, 또는 차이 > 행 수 → **판독 확인필요**.
   - 참고: 기술인A 손판독은 전 공사종류에서 이 조건을 만족(예: 교량 3,088 / 3,166, 차이 78 < 행 수).
3. 결과는 웹 결과 화면과 엑셀 하단 '판독 검증'에 기록. 실패 쪽이 있으면 엑셀 상단에 "p○○ 판독 실패 — 수동 확인 필요"를 표시한다.

## 6. 판정 규칙 (rules)

규칙·키워드·근거 조항 원문은 `criteria/2026_비탈면옹벽.yaml`에 둔다. 코드는 규칙 해석만 한다.
행마다 아래 순서로 판정하고, 처음 걸린 단계에서 결론을 낸다.

| 단계 | 판단 자료 | 결론 | 근거 |
|---|---|---|---|
| 0 기간 | 시작일·종료일 | 시작일 < 1995-01-05 → 불인정 / 종료일 '근무중' → 불인정(미준공) | 일반 5, 세부 2 |
| 1 구분 | 경력 구분 | 건설사업관리·감리경력 → 불인정 | 세부 1-나 |
| 2 용역 종류 | 사업명 | 점검·진단·성능평가 어휘 없음 → 불인정 / 급경사지 → 불인정 + 확인필요 | 세부 1-나 ① |
| 3 대상 시설 | 사업명 → 공사종류 → 공사개요 순 | 절토사면·옹벽·비탈면·사면·절개지 → 대상 / 교량·터널·제방 등만 → 불인정 / 대상·비대상 어휘 혼재 → 확인필요 | 세부 1-나 ①② |
| 4 위치 | 사업명·발주자 | 도로법 제10조 도로 → **유사** / 면도·리도·농어촌도로·학교·단지 등 → **관련** / 노선 불명 → 유사 가정 + 확인필요 | 세부 1-나 ①② |
| 5 인정율 | **사업명** | 성능평가·진단 포함 → 유사 100% / 관련 60%, 그 외 → 유사 50% / 관련 30% | 가-2 ③ |

- 도로법 제10조 도로: 고속국도, 일반국도, 특별시도·광역시도, 지방도(국가지원지방도 포함), 시도, 군도, 구도.
  유사 판정 어휘 예: 한국도로공사, 국토관리사무소, 국도유지건설사무소, 고속국도, 국도, 국지도, 지방도, 군도, 시도, 구도.
- 판정 후 부가 표시(확인필요, 노란 칸):
  - 담당업무에 성능평가·진단이 없어 사업명 기준과 다를 때 — 담당업무 기준 인정율을 근거에 병기 (가-2 ③ ※)
  - 사업명에 '정기' 점검 포함
  - 사업명·기간·인정일이 같은 행이 2개 이상
  - 관련용역 판정 건 — 건축분야 제외 해당 여부
  - 2종 정밀안전점검 인정 건 전체 — 엑셀 하단에 1회 기재 (세부 1-나 ※ 2종 증빙)
- 규칙에 없는 표현은 추측하지 않고 확인필요로 남긴다.

### Judgement (판정 결과)
`인정여부`(유사|관련|불인정), `분야`(성능평가·진단|정밀점검|-), `인정율`, `환산일수`, `근거`(문장, 쪽 번호·조항 포함),
`확인필요`(목록), `규칙ID`(어느 단계에서 결정됐는지).

## 7. 점수 (scoring)

- 환산년수 = (유사 환산일수 + 관련 환산일수) ÷ 365. (원문에 일→년 기준 없음 — 엑셀에 명시)
- 배점표(가-2 ①)는 YAML에 둔다.
  - 사업책임: 6년↑ 8.0 / 5↑ 7.2 / 4↑ 6.4 / 3↑ 5.6 / 3년 미만 4.8
  - 분야책임: 5년↑ 3.0 / 4↑ 2.7 / 3↑ 2.4 / 2↑ 2.1 / 2년 미만 1.8
  - 분야참여: 3년↑ 1.5 / 2↑ 1.35 / 1↑ 1.2 / 0.5↑ 1.05 / 0.5년 미만 0.9
- 참여형태 미선택 시 세 가지 모두 표시.
- 이적 보정계수(가 소계)는 v1에서 계산하지 않고, 근무처 정보만 엑셀 상단에 표시한다.

## 8. 엑셀 평가시트 (기술인A 최종본 양식)

- 상단: 일반사항(참여형태·성명·소속·등급), 경력 요약(인정일·인정율·환산일수·환산년수·참여형태별 점수, 수식).
- 경력 표 A~N: 분야(사업명 판정), 사업명, 시작일, 종료일, 인정일, 발주청, 공사종류, 직무분야, 전문분야, 담당업무,
  **AI 인정여부 판단**, 인정율, 환산일수(수식), **AI 판단근거**. 'AI' 머리글은 노란색.
- O열 공백, P~S **PQ 평가위원 평가**: 인정여부(유사/관련/불인정 목록), 인정율(0~1), 환산일수(수식), 평가위원 판단사유.
  위쪽에 평가위원 이름란, 평가위원 환산일수·년수·점수(수식).
- 색: 유사 파랑, 관련 주황, 확인필요 노랑.
- 하단: 판정 방법, 판정 기준(원문 요약), 확인필요 목록, 판독 검증(합계 대조표, 실패 쪽).

## 9. 웹 화면

1. **목록**: 지난 평가(성명·일시·환산년수·확인필요 건수), [새 평가].
2. **업로드**: PDF, 성명(마스킹), 소속, 참여형태(선택 안 함 가능), Gemini 전송 고지 → [판독 시작].
3. **진행**: 쪽 판독 진행률(n/N), 실패 쪽.
4. **결과**: 유사/관련/불인정 건수, 환산년수, 점수, 확인필요 건수, 합계 대조표, [엑셀 다운로드].

판독은 서버 백그라운드 작업으로 돌리고, 화면은 진행 상태를 주기적으로 조회한다.

## 10. 오류 처리

| 상황 | 처리 |
|---|---|
| API 키 없음 | 업로드 화면에서 시작 차단, 설정 안내 |
| 쪽 판독 실패 | 2회 재시도 후 실패 목록 기록, 진행 계속, 엑셀 상단 경고 |
| 분야별 인정일 쪽을 못 찾음 | 합계 대조 생략, '대조 불가' 경고 |
| PDF가 경력증명서가 아님(인적사항 쪽 없음) | 결과 화면 경고, 엑셀은 생성하되 상단 경고 |
| 엑셀 파일이 열려 있어 저장 실패 | 다른 이름(`_2`)으로 저장하고 안내 |

## 11. 시험

- **규칙 시험(정답셋)**: 기술인B(유사 35건, 1,241일), 기술인A(유사 78·관련 3·불인정 347, 인정일 2,616/29일) 손판정 결과를
  `CareerRow` JSON + 기대 판정으로 고정하고, 인정여부·인정율이 일치하는지 검사. 불일치는 규칙 수정 또는 정답 재검토 대상.
- **점수 시험**: 배점표 경계값(정확히 3년·2년 등).
- **엑셀 시험**: 생성 파일을 다시 읽어 소계·수식 참조·열 구성 확인.
- **판독 시험**: 실제 PDF 1건으로 판독 → 합계 대조가 '정상'인지(수동 실행, API 비용 발생).

## 12. 범위 밖 (다음 단계)

- 가-1 등급, 가-3·4 실적(건수·금액), 이적 보정계수
- 평가위원이 입력한 엑셀 다시 가져오기 + AI 일치율 분석
- Claude API 이중 판독
- 다중 사용자, 다른 용역·연도 기준(규칙 파일 추가로 확장 가능하게만 설계)
