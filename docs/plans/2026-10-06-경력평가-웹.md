# PQ 경력평가 웹 v1 구현 계획

**Goal:** 경력증명서 PDF 업로드 → Gemini 판독 → 규칙 판정 → 평가시트(엑셀) 다운로드.
**Architecture:** Python 패키지 `pqweb`(모듈별 단일 책임) + FastAPI 서버 + 정적 HTML/JS 화면. 평가 1건 = 폴더 1개.
**Tech Stack:** Python 3, FastAPI, uvicorn, google-genai, PyMuPDF, openpyxl, PyYAML, pytest.
**Spec:** `docs/specs/2026-10-06-경력평가-웹-design.md`

## Global Constraints
- 판정은 규칙 기반(LLM 미사용). 규칙에 없는 표현은 추측하지 않고 확인필요.
- 인정율은 사업명 기준. 담당업무가 다르면 확인필요로 병기.
- 일→년 365일. 경력 기산일 1995-01-05.
- 엑셀 열: A~N AI 판정, O 공백, P~S PQ 평가위원 평가.
- API 키·모델은 `.env`(`GEMINI_API_KEY`, `GEMINI_MODEL`).

## Tasks
1. **골격 + 모델 + 규칙 파일** — requirements, .env.example, models.py, criteria yaml, criteria.py. 시험: yaml 로드·배점표 존재.
2. **판정 규칙(rules)** — 단계 0~5 + 부가 확인필요. 시험: 대표 사례(고속국도 성능평가 100%, 국도 점검 50%, 교량 불인정, 설계 불인정, 감리 불인정, 근무중 불인정, 1995 이전 불인정, 학교 옹벽 관련 30%, 노선 불명 유사+확인필요, 급경사지 불인정+확인필요, 담당업무 차이 확인필요, 정기 혼재, 중복 기재).
3. **점수(scoring)** — 환산·배점 구간 경계. 시험: 3년 정확히, 2.99년, 참여형태 미지정.
4. **판독 대조(crosscheck)** — 형식 검사, 공사종류별 허용오차(행 수). 시험: 정상/초과/부족 초과.
5. **판독 결과 조립(assemble)** — 쪽 결과 병합, 이어지는 칸 병합. 시험: continuation 병합, 쪽 종류별 분리.
6. **PDF 쪽 변환 + Gemini 판독** — 프롬프트, JSON 파싱, 재시도. 시험: 가짜 client로 파싱·재시도.
7. **엑셀 출력** — 평가시트 양식. 시험: 다시 읽어 머리글·수식·소계 범위 확인.
8. **저장소 + 파이프라인** — 폴더 구조, status.json, 실패 쪽 처리. 시험: 가짜 reader로 end-to-end.
9. **서버 + 화면** — API 5개, 업로드·진행·결과·목록 화면. 시험: TestClient로 API.
10. **실행 스크립트·README** — run.bat, 사용법.

각 Task: 실패하는 시험 작성 → 구현 → 시험 통과 → 커밋.
