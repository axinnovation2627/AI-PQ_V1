# PQ 경력평가 웹

건설기술인 **경력증명서 PDF**를 올리면, 비탈면·옹벽 정밀안전진단 및 성능평가용역 **PQ 평가기준(2026)** 에 따라
참여기술인 경력을 판정·산정해 **평가시트(엑셀)** 를 만들고, **PQ 평가위원이 화면에서 검토·수정**하는 로컬 웹 프로그램입니다.

## 1. 무엇을 해결하나

PQ 평가위원은 경력증명서의 경력을 한 줄씩 읽고 평가기준에 따라 유사·관련·불인정과 인정율을 정해 환산년수를 계산합니다.
한 사람에 수백 건(실제 사례: 77쪽, 428건)이고, 평가자마다 해석이 갈리기 쉽습니다.

## 2. 작동 방식

```
PDF 업로드 → 쪽 이미지(150dpi) → Gemini 쪽별 판독(JSON, 여러 쪽 동시)
→ 증명서 '공사종류별 인정일수'와 합계 대조(누락·오독 확인)
→ 규칙 판정: 평가기준 YAML의 규칙으로 행마다 판정 (AI는 판정하지 않음)
→ 평가시트 엑셀 (AI 판단·근거 + 평가위원 칸)
→ 평가위원 검토 화면 → 평가위원 반영 엑셀
```

판정은 평가기준을 세 가지 기준으로 정의해 행마다 기록합니다.

| 기준 | 내용 |
|---|---|
| ① 해당분야 | 비탈면·옹벽인가 (교량·터널 등은 아님) |
| ② 용역유형 | 정밀안전진단·성능평가 / 정밀안전점검·긴급안전점검 |
| ③ 도로유형 | 도로법 제10조에 따른 도로(당해분야 → 유사용역) / 그 외(관련용역, 건축분야 제외) |

인정율(사업명 기준): 유사 100% / 50%, 관련 60% / 30%. 근거가 부족한 행은 추측하지 않고 **'확인필요'** 로 남깁니다.

## 3. 주요 기능

- PDF 업로드 → 자동 판독·판정·점수 → 평가시트 엑셀 다운로드
- 평가위원 화면: 카드 보기/표 보기, 세 기준별 AI 판단과 근거 표시, 체크한 여러 행 일괄 처리, 원본 쪽 이미지 보기, 자동 저장
- 평가기준 편집·점수 편집 화면: 어휘·규칙·인정율·배점 수정, 저장 전 검사, 백업·되돌리기, 현재 기준으로 다시 판정(API 호출 없음)
- Gemini 모델 체인(과부하·한도 시 다음 모델), 실패 쪽만 다시 읽기, 생각(thinking) 끄기로 토큰 약 40% 절감

## 4. 기술 스택

| 구분 | 사용 |
|---|---|
| 서버 | Python 3.13, FastAPI, uvicorn |
| 화면 | HTML·CSS·JavaScript (프레임워크 없음) |
| PDF·판독 | PyMuPDF(쪽 이미지), Google Gemini API(google-genai) |
| 엑셀 | openpyxl |
| 평가기준 | YAML (`criteria/2026_비탈면옹벽.yaml`) |
| 테스트 | pytest 89개 |

라이브러리 목록과 버전(SBOM): `requirements.txt`

## 5. 실행 방법 (Windows)

1. Python 3.13 설치
2. `run.bat` 더블클릭 → 처음에는 가상환경을 만들고 라이브러리를 설치합니다
3. 처음 실행 시 열리는 `.env`에 `GEMINI_API_KEY` 입력 후 저장, `run.bat` 다시 실행
4. 브라우저 `http://127.0.0.1:8765` → [새 평가] → 경력증명서 PDF 업로드

테스트: `.venv\Scripts\python -m pytest -q`

> 경력증명서 쪽 이미지가 Gemini(Google) API로 전송됩니다. 개인정보를 마스킹한 PDF 사용을 권장합니다.
> 프로그램은 내 PC(127.0.0.1)에서만 접속되도록 실행됩니다.

## 6. 바이브코딩으로 만든 과정

기획자가 말로 지시하고, 코드는 Claude Code가 작성했습니다. 2일, 커밋 26회, 코드 약 4,100줄, 자동 테스트 89개.

1. 평가기준(hwpx) 원문을 일반사항·세부사항·항목별로 매핑 — 임의 해석 없이 원문 그대로
2. 참여기술인 2명을 사람이 직접 평가해 정답지 작성
3. 설계·계획 문서(`docs/`) → 판정 규칙, 판독, 엑셀, 웹 화면 구현 (테스트 먼저)
4. 실제 PDF로 돌리며 수정: 사용량 한도·속도(병렬 판독), 토큰 절감, 화면 개선
5. 평가위원 화면, 평가기준 편집 화면, 세 가지 기준 정의로 판정 재정리

검증: 프로그램 결과가 수작업 평가와 일치 (기술인A 환산 4.90년, 기술인B 환산 2.62년).
기술인B는 같은 PDF를 Gemini와 Claude가 각각 읽어도 같은 결과가 나왔습니다.

실제 지시 예: “인정율 산정도, 사업명을 기준으로 판단해” / “AI 판단에서 해당분야·용역유형·도로유형이 뭐였는지 적어줘”

## 7. 제출본에서 바꾸거나 뺀 것

| 항목 | 처리 | 이유 |
|---|---|---|
| `.env` (Gemini API 키) | 제외 | 비밀 키. 키 없는 템플릿 `.env.example`만 포함 |
| `data/` (업로드한 경력증명서, 판독 결과, 엑셀) | 제외 | 개인정보 |
| `.git/` 히스토리 | 제외 | 추적 중인 파일만 `git archive`로 추출 |
| `.claude/` | 제외 | 개발 도구 설정 |
| 문서·테스트 속 성명·회사명·근무 이력 | 익명화 | 기술인A·B, (주)가나엔지니어링 등 가상 이름으로 교체 |
| `requirements.txt` | 버전 고정 | 실제 설치·테스트한 버전 (SBOM) |

## 8. 체험판 (Vercel 배포)

Vercel에는 **체험판**이 올라갑니다 (`api/index.py`, 환경변수 `PQ_DEMO=1`).

- 가상 기술인 1명의 예시 평가(`demo/`, `tools/make_demo.py`로 생성)를 보여 줍니다. 실제 인물·용역이 아닙니다.
- 평가위원 화면, 카드·표 보기, 엑셀 내려받기, 평가기준·점수 편집, 다시 판정을 직접 눌러 볼 수 있습니다.
- PDF 업로드·Gemini 판독은 꺼져 있습니다(개인정보·API 요금). 평가위원 입력·기준 수정은 서버 임시 폴더에만 저장되어 잠시 뒤 처음 상태로 돌아갑니다.
- 접속 비밀번호 화면은 `middleware.js` 입니다. 비밀번호 원문은 저장소에 없고, Vercel 환경변수 `PAGE_PASSWORD_SHA256` 에 SHA-256 값만 넣습니다.
- 2쪽 설명자료: `/about` (`site/index.html`)

# 원본 README

건설기술인 경력증명서 PDF를 올리면 **비탈면·옹벽 정밀안전진단 및 성능평가용역 PQ 평가기준(2026)** 의
가-2) 경력을 산정해 **평가시트(엑셀)** 로 내려준다. 평가위원은 엑셀 오른쪽 'PQ 평가위원 평가' 칸에서
AI 판단의 적정 여부를 확인·입력한다.

## 실행

1. `run.bat` 더블클릭 (처음에는 가상환경·라이브러리 설치)
2. 처음 실행 시 열리는 `.env`에 `GEMINI_API_KEY` 입력 후 저장, `run.bat` 다시 실행
3. 브라우저 `http://127.0.0.1:8765` → [새 평가] → PDF 업로드 → 판독 완료 후 [평가시트 엑셀 다운로드]

판독 모델은 `.env`의 `GEMINI_MODEL`로 바꾼다(쉼표로 여러 개: 앞 모델이 과부하면 다음 모델 사용), 동시 판독 쪽 수는 `GEMINI_WORKERS`(기본 4).
경력증명서 쪽 이미지가 Gemini(Google) API로 전송되므로 마스킹한 PDF 사용을 권장한다.

## 처리 흐름

```
PDF → 쪽 PNG(150dpi) → Gemini 쪽별 판독(JSON) → 쪽 결과 조립
    → 증명서 '공사종류별 인정일수 현황'과 합계 대조
    → 규칙 판정(R0 기간 → R1 구분 → R2 용역 → R3 대상 시설 → R4 위치 → R5 인정율)
    → 점수 → 평가시트 엑셀
```

- 판정은 규칙 기반이며 규칙·어휘·근거 조항은 `criteria/2026_비탈면옹벽.yaml`에 있다.
  규칙에 없는 표현은 추측하지 않고 엑셀에서 노란 칸(확인필요)으로 남긴다.
- 인정율은 사업명 기준. 담당업무 기준과 다르면 확인필요로 병기한다.
